重点检查：

- Serilog、NLog、ILogger、ETW、Application Insights、OpenTelemetry 等日志与追踪管道中的敏感字段记录
- 身份认证成功/失败、权限拒绝、管理操作、关键配置变更、账务操作、导入导出、租户切换是否有审计事件
- 结构化日志模板注入、message template 参数污染、异常堆栈与原始请求体写入日志的风险

- 脱敏、截断、采样、保留策略、日志轮转、集中式收集与告警规则是否导致安全事件被遗漏
- 调试级别日志、开发环境日志接管、第三方库 verbose 输出与 PII 泄露问题

## 重点检查

- 日志注入：用户输入直接进入日志消息（换行符伪造日志条目）
- 敏感信息写入日志：密码、Token、密钥、信用卡号、PII 数据
- 审计事件覆盖：认证失败/成功、授权拒绝、管理操作、数据导出是否有日志
- 异常堆栈中的敏感信息：连接字符串、内部路径、配置值
- 结构化日志的 Destructure 策略：复杂对象是否会展开敏感字段
- 日志保留与访问控制：日志文件权限、集中日志系统的访问策略
- 告警联动：高危事件是否触发实时告警

## 枚举规则（强制细化）

- 枚举所有 ILogger、Serilog、NLog、Audit.NET、Application Insights、OpenTelemetry、ETW、自定义审计服务的写日志点
- 优先搜索 LogInformation、LogWarning、LogError、Audit、TrackEvent、TrackException、BeginScope、Enrich、Destructure 等关键调用
- 枚举认证失败、权限拒绝、配置变更、管理操作、导入导出、支付、租户切换、异常回退等高价值事件是否有日志
- 对每个日志链路记录：事件类型、敏感字段、脱敏策略、保留周期、告警联动、是否可被日志注入污染
- **维度条（强制，2026-09-20）：篡改 + 淹没**——篡改面：审计日志的删除路径、级别篡改（安全事件降级为 Debug/Info）、时钟回拨对审计排序/过期判定的影响；淹没面：噪声注入（伪造低价值事件稀释审计流）与洪泛写入（高频/大体量触发存储耗尽）两条链均须给出结论（身份字段可信性与写入配额证据见本文件「机制扩展：审计完整性篡改与审计可用性淹没」节）。不适用判定条件：目标无任何审计日志写入机制，且附 rg 否定证据（范围 + 模式，如 `rg "ILogger|Serilog|NLog|Audit\." {范围}` 零命中）方可标 `不适用`；否则禁裸「未覆盖」

## Barrier 验证矩阵（强制）

按 `DOTNET_AUDIT_EXECUTION_STANDARD.md` 的 fail-close 三级标准评估：

| 等级 | 检查项 | 通过标准 | 失败降级 |
|------|--------|----------|----------|
| 一级 | 日志写入点存在且高价值事件有日志覆盖 | 存在 ILogger/Serilog/NLog 等日志写入点，且认证/授权/管理/支付等高价值事件有日志记录 | BLOCKED → 无日志机制或高价值事件未覆盖，专项结束 |
| 二级 | 敏感数据/注入可进入日志 | 用户输入直接进入日志消息（换行符伪造）、密码/Token/PII 未脱敏、异常堆栈含敏感信息 | BLOCKED → 日志无敏感数据且注入不可行，结论降级 |
| 三级 | 日志缺陷可导致安全事件遗漏或信息泄露 | 高危事件未触发告警、日志保留期过短无法复盘、日志文件权限过宽导致泄露 | PARTIAL → 仅输出潜在风险与验证步骤 |

## 二阶段判定流程（强制）

- **阶段 1（初筛命中）**：命中日志写入点 + 敏感数据/注入 + 告警/保留/权限配置，输出 `命中ID：M{hash}`。
- **阶段 2（精筛确认）**：
  1. 逆向追踪 高价值事件 → 日志写入点 → 敏感字段/用户输入 链路；
  2. 验证用户输入是否可注入日志（换行符伪造）、密码/Token/PII 是否脱敏、异常堆栈是否含敏感信息；
  3. 评估告警规则、保留周期、日志文件权限是否导致安全事件遗漏或信息泄露；
  4. 若三级 Barrier 全部通过 → `确认漏洞`；任一失败 → 按矩阵降级。

## 判定规则与优先级（强制）

1. **确认漏洞**：日志机制存在 + 敏感数据/注入进入日志 + 告警/保留/权限缺陷可导致利用。输出 `确认漏洞`。
2. **待确认**：日志机制存在但敏感数据/注入或告警证据部分缺失。输出 `待确认`。
3. **误报/无风险**：高价值事件完整覆盖、日志无敏感数据、用户输入被转义、告警规则完整、保留周期合理、权限严格。输出 `误报` 并给出判定依据。

## 测试建议与最小触发条件（强制）

- **最小触发条件**：
  - 存在日志写入机制（ILogger/Serilog/NLog）
  - 用户输入直接进入日志消息或密码/Token/PII 未脱敏
  - 或高危事件（认证失败/权限拒绝/管理操作）未触发告警
- **测试用例建议**：
  - Happy Path：正常高价值事件被完整记录，敏感数据脱敏，告警触发正确

## 机制扩展：审计完整性篡改与审计可用性淹没（2026-09-14 台账轮）

### 机制描述与边界

本扩展覆盖两条机制链：

- **完整性篡改链**：可控 header/cookie/审计字段入审计记录 → 身份冒用/错误归因。攻击者伪造身份相关字段写入审计内容，导致事后追溯时责任主体被错误归因。
- **可用性淹没链**：高频/大体量写入 → 审计存储耗尽。攻击者通过触发大量审计写入路径，使审计存储先于业务资源耗尽，造成审计证据丢失。

台账边界（逐字）：不把一般业务 DoS 升级为审计可用性问题；不把普通日志缺失归入完整性篡改。

### 重点检查与枚举抓手

每命中记录：文件、行号、写入点/消费路径、字段来源。

**完整性篡改面：**

- **审计写入点**：`ILogger` 审计级别写入、`Audit.NET` `AuditScope` / `AuditAttribute`、自定义审计中间件/过滤器。
- **身份字段来源可信性**：审计记录中的用户标识取自 `HttpContext.User` / ClaimsPrincipal 等认证主体（可信），还是直取 `Request.Headers["X-User-Id"]` / 请求体字段 / cookie 中可控值（不可信）。
- **审计字段拼接入记录**：header、cookie、查询串、请求体字段是否未经白名单/转义直接拼接进审计消息或审计实体属性。

**可用性淹没面：**

- **高频写入路径**：循环内审计写入（逐条记录循环写审计）、单请求触发多条审计（批量接口每元素一条）。
- **无节流/采样/配额**：审计写入是否有每请求条数上限、采样策略、写入队列背压；攻击者可控的批量参数（如批量大小上限）是否被审计放大。

### 验证矩阵

| Barrier 类型 | 验证动作 | 判定标准 |
|-------------|---------|---------|
| **身份字段可信源校验** | 追踪审计记录中身份字段的赋值来源，确认是否仅取自认证主体（ClaimsPrincipal / User.Identity），无直取可控 header/cookie 路径 | 身份字段全部来自认证主体 → ✅ 安全；存在可控源路径 → 🔴 高危待确认 |
| **审计字段消毒/结构化** | 检查可控字段入审计记录前是否经白名单过滤或结构化字段承载（非字符串拼接），转义是否 fail-close | 白名单+结构化承载 → ✅ 安全；原文拼接或消毒缺失 → ⚠️ 待确认 |
| **写入节流与配额** | 确认单请求审计条数上限、采样策略、队列背压是否存在且 fail-close | 有硬上限且超限拒绝/丢弃可控 → ✅ 安全；无上限或超限后静默失败 → 🔴 高危待确认 |
| **存储容量与告警** | 确认审计存储耗尽前是否有容量告警、轮转/归档策略，淹没是否可被运维感知 | 有告警+轮转 → ✅ 安全；耗尽无感知 → ⚠️ 待确认 |

🔴 **STOP：任一 barrier 验证为 `silent-fallback` 或 `fail-open` 时，禁止将结论标记为「已确认安全」或「误报」。**

### 判定规则

**完整性篡改确认**需同时闭合以下两个 EVID，缺一不可：

1. **可控字段写入路径闭合**：可控 header/cookie/审计字段实际写入审计记录的写入路径证据（`EVID_LOG_TAMPERABLE_FIELD_SOURCE`）。
2. **冒用/错误归因影响闭合**：身份冒用/错误归因影响闭合证据（`EVID_LOG_IDENTITY_MISATTRIBUTION_IMPACT`）。

**可用性淹没确认**需闭合因果链：高频/大体量写入与审计存储耗尽的因果链证据（`EVID_LOG_FLOODING_EXHAUSTION_PATH`）。

🔴 **确认阈值（台账原文）：一般业务 DoS 不得确认；普通日志缺失不属本扩展。** 完整性篡改需证明可控字段实际写入审计记录并造成冒用/错误归因；可用性淹没需证明高频/大体量写入与审计存储耗尽的因果链。

### 测试建议

- **正向**：伪造 `X-User-Id` 等 header 发起操作，确认审计记录中身份字段被冒用；以高并发/大批量请求触发审计写入，确认存储耗尽或告警。
- **负向**：身份字段仅取认证主体 + 写入节流下，伪造 header 不改变审计归因，高频写入被限流。
- **回归**：新增审计字段或新增批量端点时，复核字段来源可信性与写入配额。

### 证据引用

- `EVID_LOG_IDENTITY_MISATTRIBUTION_IMPACT`：身份冒用/错误归因影响闭合证据（完整性闭合第二 ID）
