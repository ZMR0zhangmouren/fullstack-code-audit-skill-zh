- 管理后台、批处理接口、导入导出、定时任务、Webhook 回调与前台接口之间权限和约束不一致
- 审计日志、告警、补偿逻辑和失败回退是否足以防止逻辑缺陷被持续利用

## 重点检查

- Mass Assignment：DTO 缺少 [BindNever]/[JsonIgnore] 的敏感字段（角色、余额、状态）
- 竞态条件：余额/库存/计数器的 check-then-act 模式缺少并发控制
- 状态机缺陷：订单/支付/审批流程的非法状态跳转
- 幂等性缺失：重复提交导致重复扣款/发放/审批
- 批量操作：批量接口缺少逐条权限校验或数量限制
- 业务规则绕过：优惠券叠加、负数金额、边界值、类型混淆
- JsonPatchDocument.ApplyTo：Patch 操作覆盖受保护字段
- 多入口操作同一资源：不同接口对同一实体的修改缺少一致性校验

## Barrier 验证矩阵（强制）

按 `DOTNET_AUDIT_EXECUTION_STANDARD.md` 的 fail-close 三级标准评估：

| 等级 | 检查项 | 通过标准 | 失败降级 |
|------|--------|----------|----------|
| 一级 | 业务状态变更入口存在 | 存在涉及支付/库存/审批/权限/租户的状态变更业务接口且用户可触发 | BLOCKED → 无业务状态变更入口，专项结束 |
| 二级 | 状态机/并发/幂等存在缺陷 | 状态机存在非法跳转、check-then-act 无并发控制、幂等键缺失、批量操作无逐条校验 | BLOCKED → 状态机/并发/幂等控制完整，结论降级 |
| 三级 | 缺陷可导致实际业务损失 | 非法状态跳转/竞态/重放可导致重复扣款/超发/越权审批/数据污染 | PARTIAL → 仅输出潜在风险与验证步骤 |

## 二阶段判定流程（强制）

- **阶段 1（初筛命中）**：命中业务状态变更入口 + 状态机/并发/幂等配置 + 业务影响面，输出 `命中ID：M{hash}`。
- **阶段 2（精筛确认）**：
  1. 逆向追踪 业务动作入口 → 前置校验 → 状态机约束 → 最终敏感操作 链路；
  2. 验证状态机合法/非法分支、check-then-act 竞态窗口、幂等键与分布式锁覆盖；
  3. 评估非法状态跳转/竞态/重放是否可导致实际业务损失（重复扣款/超发/越权）；
  4. 若三级 Barrier 全部通过 → `确认漏洞`；任一失败 → 按矩阵降级。

## 判定规则与优先级（强制）

1. **确认漏洞**：业务状态变更入口可触发 + 状态机/并发/幂等缺陷 + 可导致实际业务损失。输出 `确认漏洞`。
2. **待确认**：业务入口存在但状态机/并发/幂等证据部分缺失。输出 `待确认`。
3. **误报/无风险**：状态机严格校验所有分支、check-then-act 有分布式锁/乐观锁、幂等键完整、批量操作逐条鉴权。输出 `误报` 并给出判定依据。

## 测试建议与最小触发条件（强制）

- **最小触发条件**：
  - 存在业务状态变更接口（支付/库存/审批/权限/租户切换）
  - 用户可触发该接口
  - 状态机存在非法跳转、或 check-then-act 无并发控制、或幂等键缺失

## 机制扩展：整数溢出（2026-09-14 台账轮）

### 机制描述与边界

用户数值 → 整数算术 → 溢出致逻辑失败/可用性损失。攻击者提交边界外数值（极大值、负值），使 unchecked 算术在 `int` / `uint` / `long` 等定宽类型上回绕，导致价格计算错误、长度/偏移异常、权限判断绕过或拒绝服务。

台账边界（逐字）：纳入既有数值校验维度，不新建算术 Skill。

### 重点检查与枚举抓手

每命中记录：文件、行号、算术点、涉及类型与边界来源。

- **用户可控数值入算术**：`int.Parse` / `Convert.ToInt32` / `int.TryParse` 解析请求参数后参与加减乘；模型绑定直接得到的数值字段进入运算。
- **unchecked 默认上下文**：关键算术点缺少 `checked` 块或项目级 `<CheckForOverflowUnderflow>` 未开启，默认 unchecked 回绕。
- **长度/偏移计算**：数组分配（`new byte[len]`）、`Span` 切片、`Skip` / `Take` 分页参数参与算术后再作长度，乘法溢出致分配过小。
- **货币/积分换算**：分↔元乘除（`amount * 100` / `cents / 100`）、汇率乘除，中间结果超 `int` 范围。
- **自增/累计器**：计数器、序号生成器无上限保护，达到 `int.MaxValue` 后回绕。

### 验证矩阵

| Barrier 类型 | 验证动作 | 判定标准 |
|-------------|---------|---------|
| **边界检查前置** | 确认算术运算前是否做 min/max 边界校验（如 `amount > 0 && amount <= LIMIT`），校验是否 fail-close | 前置校验 fail-close → ✅ 安全；无校验或校验后可绕 → 🔴 高危待确认 |
| **checked 上下文强制** | 确认关键算术点是否 `checked` 包裹或项目级溢出检查开启 | 关键算术 checked → ✅ 安全；关键算术 unchecked 且无前置校验 → 🔴 高危待确认 |
| **类型宽度匹配** | 确认运算前是否升级至 `long` / `decimal`，中间结果是否超 `int` 范围 | 宽度充足 → ✅ 安全；中间结果溢出 → ⚠️ 待确认 |
| **回绕防护** | 确认累计器/计数器达上限时的处理（拒绝、重置、告警），非静默回绕 | 安全处理 → ✅ 安全；静默回绕 → ⚠️ 待确认 |

🔴 **STOP：任一 barrier 验证为 `silent-fallback` 或 `fail-open` 时，禁止将结论标记为「已确认安全」或「误报」。**

### 判定规则

确认需同时闭合以下三个 EVID，缺一不可：

1. **用户源闭合**：用户可控数值进入算术运算的源定位证据（`EVID_LOGIC_NUMERIC_USER_SOURCE`）。
2. **算术点闭合**：加减乘/长度偏移/货币积分换算等算术运算点证据（`EVID_LOGIC_ARITHMETIC_POINT`）。
3. **影响闭合**：溢出或边界绕过导致逻辑失败/可用性损失的影响证据（`EVID_LOGIC_OVERFLOW_IMPACT`）。

🔴 **确认阈值（台账原文）：需证明溢出或边界绕过，非仅存在数值转换。**

已 checked + 前置边界校验为误报。

### 测试建议

- **正向**：以 `int.MaxValue` 金额、负长度、超大分页参数触发边界输入，确认溢出改变逻辑结果（价格回绕、分配异常、判断绕过）。
- **负向**：`checked` + 前置边界校验下，边界输入抛异常或被拒绝，逻辑结果不变。
- **回归**：新增数值字段、分页参数、金额/积分换算时，复核边界校验与 checked 覆盖。

### 证据引用

- `EVID_LOGIC_NUMERIC_USER_SOURCE`：用户可控数值进入算术运算的源定位证据
- `EVID_LOGIC_ARITHMETIC_POINT`：加减乘/长度偏移/货币积分换算等算术运算点证据
- `EVID_LOGIC_OVERFLOW_IMPACT`：溢出或边界绕过导致逻辑失败/可用性损失的影响证据
